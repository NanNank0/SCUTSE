# BST结点与高度
对应源码：`exp2-1/search_tree.h`；`exp2-2` 使用同一份算法实现，并在构造时启用 AVL 模式。

每个结点保存键值、高度、左孩子、右孩子。BST 满足左子树值小于根值，右子树值大于根值。本项目不保存重复键。

高度约定为：空树高度 0，单结点高度 1。`update` 使用 `1 + max(左高度, 右高度)` 更新当前结点。

`root_` 管理根结点，根结点又管理孩子，形成完整的所有权链。图形窗口通过只读指针观察树，不取得结点所有权。

# unique_ptr与std move

`std::unique_ptr<Node>` 独占单个结点，结点的左右孩子也使用 `unique_ptr`，形成从根到叶子的所有权链。清空根指针后，孩子随结点递归释放，不需要手工逐个 `delete`。

它不能直接复制，因为两个指针不能同时独占同一个结点。树在删除和旋转时通过 `std::move` 转移所有权：

```cpp
auto q = std::move(p->right);
```

这一行没有复制整棵子树，而是把原右孩子的所有权交给 q；原来的 `p->right` 变为空。`std::move` 本身表达“允许移动”，真正的转移由目标对象的移动操作完成。

参数 `std::unique_ptr<Node>& p` 是指针对象本身的引用。递归插入、删除或旋转可以借它更换父结点持有的子树根。

`p->left.get()` 返回供观察的普通指针，不转移所有权。窗口刷新期间用这些指针读取结点，不能在删除结点后继续使用旧指针。

# 树的find方法
从根开始比较：目标值较小就向左，较大就向右，相等则返回当前结点指针；走到空指针表示不存在。

只沿一条路径前进，时间为 O(h)、额外空间为 O(1)。普通 BST 最坏会退化为高度 n 的链；AVL 保证高度为 O(log n)。

# 树的insert方法
公开的 `insert` 检查键值范围，调用内部 `insertAt`，仅在真正插入时把结点数加一。

`insertAt` 使用递归：遇到空子树就创建结点；遇到重复值返回 false；其余情况按大小关系递归进入左右子树。返回时调用 `rebalance` 更新高度，AVL 模式还会修复失衡。

参数 `std::unique_ptr<Node>& p` 是“指针对象本身的引用”。当插入或旋转需要更换子树根时，可以直接修改父结点持有的那个指针。

# 树的remove方法
删除分三种结构情况：

1. 没有孩子：把该子树根变为空
2. 只有一个孩子：让唯一的孩子接替当前结点
3. 有两个孩子：找到右子树中最小的键，即中序后继；用后继键替换当前键，再到右子树删除原后继

前两种情况在代码中统一为“没有左孩子就让右侧接替，否则没有右孩子就让左侧接替”。两个孩子都没有时，接替指针本来就是空指针。

公开 `remove` 只减少一次总数。内部删除后继没有再次调用公开方法，所以不会把一次逻辑删除错误地计为两次。

# rotateLeft方法
用于右侧过高的旋转。设原根为 p，右孩子为 q：先保存 q，把 q 的左子树交给 p 的右侧，再让 p 成为 q 的左孩子，最终 q 成为新根。

```text
    p                q
   / \              / \
  A   q     →      p   C
     / \          / \
    B   C        A   B
```

旋转前后的中序都是 `A、p、B、q、C`，因此不会破坏 BST 的有序关系。旋转只改少量指针，时间为 O(1)。

# rotateRight方法
右旋与左旋对称：左孩子上升为新根，原根下降为右孩子，左孩子原来的右子树转移到原根的左侧。

两种旋转都应先更新下降结点的高度，再更新新根高度。因为新根高度依赖更新后的孩子高度，更新顺序不能颠倒。

# rebalance方法与四种失衡
平衡因子定义为 `b = h(left) - h(right)`。AVL 要求每个结点的平衡因子在 -1、0、1 之间。

| 情况 | 特征 | 修复 |
|---|---|---|
| LL | 左侧高，左孩子的左侧不低于右侧 | 当前结点右旋 |
| LR | 左侧高，左孩子的右侧更高 | 先左旋左孩子，再右旋当前结点 |
| RR | 右侧高，右孩子的右侧不低于左侧 | 当前结点左旋 |
| RL | 右侧高，右孩子的左侧更高 | 先右旋右孩子，再左旋当前结点 |

删除时，较高孩子的平衡因子可能恰好为 0，这时仍然用相应的单旋。删除还可能使多个祖先失衡，必须在递归返回时逐层修复，不能旋转一次就提前退出。

可清空 AVL 后，分别逐个插入 `30 20 10`、`30 10 20`、`10 20 30`、`10 30 20`，观察四种情形。最终根都应为 20。整组“构建”按钮要求至少 8 个值，所以三结点实验使用逐个插入。

# traverse方法与leaves方法
先序访问顺序为“根、左、右”，中序为“左、根、右”，后序为“左、右、根”。代码通过调整 `values.push_back` 的位置复用同一种递归结构。

BST 的中序结果递增，可以用来检查插入和删除是否保留有序性。不同形状的 BST 可能拥有相同中序结果，因此仅看中序还不能证明高度维护或 AVL 平衡性正确。

`leaves` 只收集左右孩子都为空的结点。空树的叶子数是 0，单结点树的叶子数是 1。两种方法均访问每个结点一次，为 O(n)。

# QApplication与main函数

对应 `exp2-1/main.cpp` 与 `exp2-2/main.cpp`。下面展开普通 BST 入口的主要步骤：

```cpp
QApplication app(argc, argv);
styleApp(app);
TreeWindow window(false);
window.show();
return app.exec();
```

`false` 表示普通 BST；AVL 入口使用 `TreeWindow window(true)`，启用平衡维护。源码还调用 `setupCapture` 配置截图辅助功能，这里只列出窗口启动的核心过程。

`QApplication` 管理图形应用，`show()` 显示窗口，`app.exec()` 进入事件循环，等待鼠标、键盘和窗口事件。没有事件循环，程序可能创建完窗口就结束。

`argc` 和 `argv` 是启动参数入口，日常使用仍然可以通过图形窗口操作。

# QWidget与布局

`QWidget` 是树窗口的基础类，`QPushButton` 是按钮，`QLineEdit` 输入整组序列，`QSpinBox` 输入单个结点值，`QComboBox` 选择示例序列，`QLabel` 显示统计和遍历结果，`QPlainTextEdit` 显示操作记录。

`QVBoxLayout` 纵向排列控件，`QHBoxLayout` 横向排列控件。布局比给每个控件指定固定坐标更容易适应不同窗口尺寸。树图内部的结点坐标则由绘图算法计算，和窗口控件布局是两个层次。

Qt 的父子对象机制负责销毁子控件。`new QVBoxLayout(this)` 将布局交给窗口，加入窗口布局的控件也由窗口层级管理；树结点由 `unique_ptr` 管理。

# connect与lambda表达式
对应 `ui_common.h` 中的 `action`：

```cpp
QObject::connect(button, &QPushButton::clicked, owner, [owner, fn] {
    fn();
});
```

`button` 是发出信号的对象，`clicked` 是点击信号，`owner` 是连接上下文，lambda 是点击后执行的函数。上下文对象销毁后，Qt 会使这个连接失效。可对照 [Qt 信号与槽文档](https://doc.qt.io/qt-6/signalsandslots.html) 和 [QObject 连接接口](https://doc.qt.io/qt-6/qobject.html#connect) 阅读。

方括号是 lambda 捕获列表。`[this]` 捕获当前对象指针，`[owner, fn]` 按值保存指定变量，`[&]` 按引用捕获，`[=]` 默认按值捕获需要使用的局部变量。在 C++17 中，`[=]` 使用成员时会捕获 `this` 指针，并不是复制整个窗口对象。

异步执行的回调不能引用已经销毁的局部变量。本项目按钮回调所需的控件是窗口成员，公共函数的连接也绑定了窗口生命周期。

# 一次点击如何调用insert

调用顺序是：按钮发出 `clicked` → `action` 执行回调 → `key->value()` 读取结点值 → `tree.insert` 更新树 → `refresh` 重画树并更新统计 → 写入操作记录。

下面是便于跟读的简化片段，源码还保存了操作前后的中序序列：

```cpp
action(controls, "插入 Insert", "insert", this, [=] {
    bool ok = tree.insert(key->value());
    selected = key->value();
    refresh();
    log->appendPlainText(ok ? "插入成功" : "重复值，不重复插入");
});
```

`"insert"` 这个对象名供界面检查定位按钮，真正调用算法的是 `tree.insert(...)`。`selected` 决定橙色高亮，`refresh` 显示算法已经生成的树形。

查找只改变高亮状态，不改变树结构；插入重复值返回 false，树中不会出现第二个相同键。

# buildSequence方法与输入检查

整组构建从 `sequence->text()` 读取文本，按空白、逗号或分号切分。使用 `toInt(&ok)` 将每项转成整数，通过 `ok` 检查转换是否成功，不能把转换失败得到的值当作合法输入。

构建要求输入 8 到 101 个不同整数，每个值在 0–100。`std::set<int> seen` 仅用于检查重复输入，实际树仍由 `SearchTree` 的指针结点保存。

只有全部输入通过检查后，程序才清空旧树，再按输入顺序插入。整数格式、范围或重复检查失败时，旧树保持不变。单个插入使用整数控件，允许在空树中逐个添加少于 8 个结点。

当前树窗口通过输入框或下拉框取得序列，没有文件导入和保存按钮。测试数据中的序列可复制到输入框。

# 异常与操作结果

整组输入不合法时，`buildSequence` 抛出 `std::invalid_argument`。公共 `action` 通过 `try/catch` 捕获 `std::exception`，把错误写入操作记录区，让窗口继续响应后续操作。

树接口用返回值表示常见的未成功操作：`insert` 遇到重复键返回 false，`remove` 遇到不存在的键返回 false，`find` 未找到时返回空指针。它们不应被当成程序崩溃，也不能显示为操作成功。

捕获异常不代表回调正常结束。发生异常后，不会继续执行回调中尚未运行的成功提示。

# QString与整数序列

Qt 控件使用 `QString`。`sequence->text()` 得到输入文本，`split` 按分隔规则切成多项，`toInt(&ok)` 转换并验证整数，`QString::number()` 将结点值转换成显示文本。

树遍历返回 `std::vector<int>`。窗口的 `join` 方法将每个整数转成字符串，再用 `QStringList::join` 拼接显示。

`arg()` 把值填入 `%1`、`%2` 等占位符，例如把结点数、树高和叶子数写入状态标签。异常信息通过 `QString::fromUtf8(e.what())` 转换成界面文本。

# 树图如何绘制
对应 `tree_window.h` 的 `refresh`。先中序遍历：每访问一个结点，让横坐标编号加一；递归深度决定纵坐标。于是左子树位于根左边，右子树位于根右边。

接着先画父子之间的线，再画圆和键值，防止线压住结点。`QGraphicsScene` 保存图形项，`QGraphicsView` 显示场景，`fitInView` 按比例缩放整棵树。

绘图每次根据当前树重新生成。它显示的是算法已经产生的结果，不参与决定 BST 插入位置或 AVL 旋转方向。

# CMake与图形界面运行

本实验使用 Qt 6.5 以上、C++17 和 CMake 3.21 以上。可以在 Qt Creator 中打开本文件夹的 `CMakeLists.txt`，选择与已安装 Qt 库匹配的构建套件，再点击构建和运行。也可以单独打开某个 `exp` 文件夹中的 `CMakeLists.txt`。构建成功后，程序通过窗口和按钮操作。

Qt 工程需要编译器知道 Qt 的头文件位置，还需要链接 Qt 的库。普通的“编译当前 cpp 文件”没有这些信息，可能报 `QtWidgets: No such file or directory`。

`find_package(Qt6 ... Widgets)` 找到 Qt，`target_link_libraries(... Qt6::Widgets)` 把所需头文件路径和链接依赖加到目标上。

如果使用 VS Code，应通过 CMake Tools 配置整个工程，选择与 Qt 匹配的编译器，并让 CMake 找到对应的 Qt 安装目录。配置时找不到 Qt，可以设置 `CMAKE_PREFIX_PATH` 为 Qt 套件目录，例如本机的 `C:/Qt/6.11.1/mingw_64`。换电脑时应使用实际安装路径。

目录调整后，原有运行配置中的旧路径可能失效，需要指向当前工程构建出的程序。修改源码后先重新构建，再运行。只启动旧的可执行文件，会继续看到旧界面；逐行断点调试还需要选择包含调试信息的构建。

# 验证代码是否正确

可以用 `std::set<int>` 作为树操作结果的参照，对同样的插入、查找和删除比较返回结果与中序序列。标准容器用于核对，不替代实验的树实现。

仅比较中序还不够，每次操作后还应检查左右子树有序性、结点数和存储高度。AVL 还要求每个结点的左右高度差不超过 1。

手工检查时至少覆盖：

1. 清空后结点数、树高、叶子数均为 0；插入一个结点后均为 1
2. 重复插入不增加结点数，查找或删除不存在的键不破坏原树
3. 分别删除叶子、只有一个孩子的结点、两个孩子的结点以及根结点
4. 清空 AVL 后分别逐个插入四组三结点序列，验证 LL、LR、RR、RL 旋转
5. 连续删除后检查所有祖先的高度和平衡，不能只检查根
6. 输入重复值、非整数、越界值或不足 8 项的整组序列，检查提示和原树是否保留

两题都构建序列 B：`10 20 30 40 50 60 70 80 90`。普通 BST 会退化为高度 9 的链；按当前 AVL 算法构建的树高为 4。两者中序应相同，可以直观看到平衡维护对树高的影响。
